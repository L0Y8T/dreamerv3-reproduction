## 2 这个结果能说什么、不能说什么

**能说：**
1. **管线端到端可用**：训练 → `metrics.jsonl` / event → `export_r2d.py` → JSONL（首行 config、末行 summary）→ `table_r2d.py` → 表 + 2·SE + 曲线图，6 个 seed 全自动走通，重复跑三次结论一致。
2. **两臂都在学，而且学得不慢**：起点 ~19（随机策略）→ 末窗口均值 ~104-108，Δ/SE 分别 6.35 与 4.23，远超 2·SE 门槛。这**不是**"没跑起来"。
3. **两臂在这个预算下分不开**：\|Δ\|/SE = 0.16。按项目统一口径（Welch，2·SE），**必须写「未区分」**，
   **不许**因为"r2dreamer 是 2026 SOTA、作者说它更快"就写成它更好。
4. **dreamer 的种子方差显著大于 r2dreamer**（0.444 vs 0.076），这是本轮唯一一条两臂之间的差别信号，
   但 n=3、且判据 3 未区分 ⇒ 只能写成"**观察到的迹象**"，**不能写成结论**。

**不能说：**
1. **不能说"复现成功"**：预算只有设计值的 3.9%，没有和论文数字对标（那属 W8 的 A 路线）。
2. **不能当 W7 的基线分数**：W7 验收要求「满预算 5.1e5 的 DreamerV3 曲线」，本轮是 2e4。
3. **不能说 r2dreamer 更稳**：3 seeds、单任务、单预算，样本量支撑不了稳定性结论。
4. **不能说 `episode/score`（训练回报）**：那是训练回报，主指标只认独立 eval 的 `episode/eval_score`。

## 4 慢在哪（决定了后面为什么不能跑满预算）

| 项 | 实测（`results\E0_diagnose.json`） |
|---|---|
| 每轮 32 env 步里，环境步进占多少时间 | 0.142 s（**3.9%**，eval 段实测纯环境速率 224.9 步/s） |
| ⇒ 反推每次 optimizer update | **0.435 s**（2.3 update/s），**96% 的时间在梯度更新** |
| 更新期 GPU 利用率 | 中位 **15%** / p90 32% / max 41% |
| 也就是说 | **不是算力不够、不是显存不足、不是环境仿真慢**，是 eager 逐算子调度在等 CPU |

`torch._dynamo.exc.BackendCompilerFailed: backend='inductor' ... Cannot find a working triton installation`。
⇒ 全部 arm 统一 `model.compile=False`（两臂逐项相同），代价 ~6× 吞吐。

## 6 判据 2 不通过（dreamer）的排查（设计 §6 要求）

设计 §6 第一条对应症状是「不同 seed 差异巨大 → 环境侧种子没固定」。**逐条查过，不是这个原因**：

| 检查 | 结果 |
|---|---|
| `env.seed` 是否真的被 hydra 覆盖 | 是：三个 seed 的 `env.seed` = 0/1/2（`.hydra/config.yaml` 实测） |
| `env_num` / `eval_episode_num` 是否一致 | 一致（16 / 10），三 seed 相同 |
| 是不是某一 seed 崩了/早停 | 否：6 个 seed 全部 `exit 0`、全部 19008 步、全部 20 个 eval 点 |
| 曲线形态是否异常 | 否：三个 seed 都在 8000–10000 步后明显抬升（逐 seed 末窗口均值 55.02/106.99/145.78 对应 Δ=65.40/78.45/110.34） |

**能说的**：dreamer 三个 seed 的**学习速率**差别本来就大（Δ 从 65 到 110），在这个预算下最终分落到 55–146 属同一种形态、不同相位，不是管线错误。
**要一起写明的**（交接 §5 的坑）：`envs\__init__.py:60` 是 `seed = config.seed + id`，
所以**不同 seed 之间的 eval 初始条件集合是不一样的**（同一 seed 下两臂才共用同一套 eval 初始条件）。
⇒ 判据 2 的跨 seed 离散度里混着「eval 集合不同」这一层，3 seeds 下无法分离。**这就是为什么本轮不把它当结论写。**
