### ☐ 3.7 判定（判据在跑之前就固定在设计文档 §3，不许事后改）

三个判据的**精确算法**（照抄实现，别自己改口径）：

```text
① 曲线真的在学（within-run 差值，across-seed 检验）
   W = max(2000, 预算 // 5)        # 比例窗口；预算=2e4 时 W=4000
   前置条件：预算 ≥ 2.5 × W，否则判据 1 记「不适用」
   对每个 seed：d_i = mean(eval_score over step ∈ 最后 W 步) − mean(eval_score over step ∈ 最前 W 步)
   汇总：mean_d = fmean(d_i)，SE_d = sd(d_i, ddof=1) / sqrt(n)
   判定：mean_d > 2·SE_d  ⇒ 通过
   注：不能用「两个窗口的均值各算 sd 再拼 Welch」——那会把同一条曲线内的自相关当成独立样本。
   注：窗口**不许写死 1e5**。预算 ≤ 2×窗口时两个窗口重合、d_i 恒为 0，判据 1 会恒不通过
       （2026-11-02 就是这么发现的，见 §3.4 实测结论）。

② 跨种子稳定（改用相对离散度，并加绝对兜底）
   通过条件：sd(最终 eval_score) / |mean(最终 eval_score)| < 0.25
   **且** mean(最终 eval_score) > 0
   若 mean ≤ 0（例如全是 0 分）：判据 2 直接记为「不适用（曲线本就没学）」，不要算出一个巨大的比值当结论。

③ 两档可分（仅当 E1/E2 都跑满）
   Welch：SE = sqrt(sd1²/n1 + sd2²/n2)，|Δ| > 2·SE 才算分开，否则写「未区分」。
   注：同一 seed 下两臂的 eval 环境初始条件相同（envs\__init__.py 用 seed+id），
   理论上可以做成配对比较、功效更高；但本项目统一口径是 Welch，**不许临时换方法抬高功效**。
```

### 7.3 STOP 条件（只有这三条允许停下来等人）

1. **STOP-1 数据可能被污染**：发现已有 `results\*.jsonl` 或 `logdir\` 来自别的配置却被当成同一组，且已无法区分来源。

3. **STOP-3 环境被卡死**：缺包且无法绕过；或 venv 损坏；或训练入口本身跑不起来。

停的方法：**不要干等**。写一份 `停在这里_<日期时间>.md`，含「卡在哪 / 已试过什么 / 实测数字 / 建议的下一步」，

## 9 待机协议（子 agent 模式，2026-11-02 启用）

> 这一节的存在前提：干活的是**主会话的子 agent**，不是独立窗口。
> 主会话（下称「主窗口」）平时**不占用任何东西**，只在被叫醒时读文档、回一句、继续睡。

### 9.1 通道

```
K: 子 agent → 主窗口：用 send_message（这是唯一能"叫醒"主窗口的动作）。
K: 主窗口 → 子 agent：同样用 send_message；你 idle 时它会直接给你起一轮。
K: 两端都不许用 ask_user_question —— 那会挂起等人回答，人不在就是白等一夜。
```

### 9.2 什么情况才叫醒（**别滥用，叫醒是有成本的**）

| 级别 | 情形 | 动作 |
|---|---|---|
| **P1 叫醒** | 命中 §7.3 的 STOP；设计本身有错；数据出现无法解释的矛盾；卡死且绕过会影响判据 | 写 `问你.md` + `send_message` 给主窗口 + **按默认分支继续跑** |
| **P2 只写文件不叫醒** | §7.2 决策表覆盖的所有自助决定 | 只在 `进展.md` 追加一行 + 最终报告里记，**不发消息** |
| **P3 跑完** | 全部 6 个 seed 跑完并导出出表 | `send_message` 一次，附结论三句 + 文件路径 |

⚠️ **跑完一个 seed、E0 出结果这种进度，属于 P2，不许发消息。** 主窗口不需要被进度叫醒。

### 9.3 `问你.md` 的格式（**追加式，不许覆盖历史**）

```markdown
## Q1 · 2026-11-03 04:12
**问题**：（一句话，具体到能一句话回答）
**已经试过什么**：（命令 / 输出 / 报错最后 20 行）
**不决定会怎样**：（影响哪些数据；能不能先继续）
**我的建议 + 默认分支**：建议 A；若无人回答，我按 A 继续，理由……

<!-- 主窗口在这里回答，她只追加，不改上面的 Q 块 -->
### A1 · 由主窗口回答
（回答内容 + 依据）
```

- 编号必须连续，一个问题一块
- **发消息前先检查文档里有没有"已答未读"的 A 块** —— 有就先读完再用，别重复问
- 叫醒用的消息要短，只做唤醒：`Q2 已写入 问你.md，我按默认分支继续`

### 9.4 主窗口被叫醒后做什么

```
1. 读 问你.md 里最新的 Q 块（只读最新的，别通读全文）
2. 在同一个 Q 块下面追加一个 A 块（结论 + 依据 + 如果我的建议是"改设计"要说清改哪儿）
3. send_message 给子 agent 一行：A2 已写入
4. 结束这一轮 = 继续待机
```

### 9.5 兜底（主窗口**不会**自己发现子 agent 死了）

```
X: 如果子 agent 静默死掉（进程被杀 / OOM 到没写出异常 / harness 崩），没有人会通知主窗口。
   ⇒ 唯一兜底是 `进展.md` 的最后一行时间戳，由**用户**早上第一次看时发现。
X: 所以「每完成一步就往 进展.md 追加一行带时间戳的记录」是硬要求，不是可选项。
O: 训练子进程即使 agent 死了也可能还活着（Windows 不默认杀子进程），
   但没人收结果 —— 这种情况下用户看到的现象是「logdir 文件还在变大，但 进展.md 不动」。
```

### 9.6 出现多个执行者时怎么办（2026-11-02 实战补充）

```
K: 2026-11-02 凌晨实际出现了两个 agent 同时跑同一组实验（用户先开了新窗口、又开了本窗口的子 agent）。
   训练撞车靠 .run_repro.lock 串行化能解决，但有两件事锁管不了，必须靠分工：
   ① 导出/出表/回填账本 —— 会产生重复条目与互相矛盾的结论
   ② 谁也不知道对方会不会用 ask_user_question 挂在半夜等人

X: 分工规则（两个执行者同时存在时按这个走）：
   1) **训练：谁先拿到锁谁跑**。后到的一方不许抢跑同一个 seed，只能等锁或跳过已完成的。
   2) **收口（导出/出表/判定/回填三本账）：只由一人做**，通常是「知道 §9 待机协议、能被主窗口叫醒」
      的那一方 —— 因为另一方可能半夜挂在提问上。
   3) **增量导出**：每完成一个 seed 就导出一次 JSONL，别等全部跑完。这样对方崩了数据仍在。
   4) 禁止：kill 别人的进程、--force、删 logdir、并发两个训练进程。
X: 三本账若已被另一方写过，**只追加不删**，并在实验记录里注明「同一事件可能有两份记录，以本节为准」。
```

看 `进展.md` 的最后一行时间戳，就知道进度到哪、有没有断。
